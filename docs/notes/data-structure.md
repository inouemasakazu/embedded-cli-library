# データ構成 検討メモ

## データ構成

### 方針
利用者が使用する必要のある公開データは仕様を明確にしておく。  
非公開データに関しては、柔軟に対応してよいこととして、本文書には記載しない。  


ライブラリとしては、マルチインスタンスに対応するため制御データは構造体で一元管理とする。  
制御用のstaticデータ等は定義しない。必要なデータはすべて構造体に責務を持たせること。  

インスタンス用の構造体は、`不透明型`を採用し外部公開するAPIを介してのみ制御データへのアクセスは許可される。  
利用者の環境に応じた設定が行えるように`設定用`の構造体を定義する。  

---



### 不透明型
インスタンス用の公開構造体として不透明型を定義する。  
構造体は128byteのメモリ領域を使用する。  

```h
typedef struct
{
    /* 将来の拡張を考慮し、メモリは128byteを確保する */
    uint8_t opaque[128]:
} cli_handle_t;
```

利用者は、「cli_handle_t」を用いてインスタンスを静的確保する。  
```c
/* 利用者のアプリケーションに実態を定義 */
static cli_handle_t handle;
```

### 設定用
利用者が指定する設定用データは`cli_config_t`に定義し、外部公開する。  

コールバックの関数ポインタや、利用者が保証する「workspace」のメモリレイアウトの指定用データは本データに含める。  
初期化、設定用APIを介して内部データに反映される。  

```h
typedef struct
{
    /* 利用者が個別に設定するデータを定義 */
    /* コールバック */
    int (*io_write_cb)(const char *p, uint32_t s);

    /* workspaceのメモリレイアウト設定用データは「cli_config_t」に配置する */
    uint32_t max_line_length;
    uint32_t history_depth;
    uint32_t max_io_write_length;
} cli_config_t;
```

#### メモリレイアウト設定用データ
`cli_config_t`内に`workspace`のメモリレイアウトを設定用データが含まれる。  
CLIライブラリの初期化時に、設定用データと`workspace`が保証するメモリ領域をもとにメモリレイアウトを決定・管理する。  


---


### workspace
CLIライブラリは、コマンドライン・履歴用のバッファは有さない。  
アプリケーションが必要とするコマンド長・履歴データの必要有無に応じて、利用者がメモリ領域を保証する。  

静的確保したメモリ領域を初期化用APIに渡すことで、CLIライブラリはバッファを確保する。  

```h
/**
 * @brief CLI初期化
 * @param hdl CLIの制御データ用インスタンス
 * @param cfg 利用者が指定する設定データ
 * @param workspace 利用者が保証するメモリ領域
 * @param size workspaceのサイズ
 * @return 処理結果
 */
int cli_init(cli_handle_t *hdl, const cli_config_t *cfg, void *workspace, size_t size);
```

`workspace`と`cli_config_t`で指定された`workspace`用パラメータをもとに、メモリレイアウトを算出し各データ用に割り振られる。  

```text
+----------------------+----------------------+
|  workspace           |  line buffer         |
+----------------------+----------------------+
|  workspace + offset  |  history             |
+----------------------+----------------------+
|  workspace + offset  |  tokenizer (**argv)  |
+----------------------+----------------------+
|  workspace + offset  |  printf buffer       |
+----------------------+----------------------+
```
