# CLIライブラリ 検討メモ

## 目的
CLI(Command Line Interface)とは、キーボードから文字を入力して、WindowsやLinux等のコンピューターを操作する仕組み・機能のことを指す。  
本文書では、マイコン向けにCLIの仕組み・機能を実現するライブラリの検討内容を記載する。  

---



## 概要
CLIライブラリは、入力データの解析、コマンドの実行、解析・実行結果の出力を責務とする。  

```text
キーボードから文字を入力
↓
CLIライブラリ
(入力データの解析、コマンドの実行、解析・実行結果の出力)
↓
コンソールに入力結果を描画
```


使用する入出力デバイス(キーボード・コンソール等)に依存するロジックは責務としない。  
CLIライブラリが指定するデータフォーマットに従ってデータの入出力を行う必要はあるが、CLIライブラリが指定する動作環境にも制約はない。  

使用する環境に応じた入出力モジュールを用意すれば、例えば、PC上で動作するターミナルソフトや、LCD/OLEDデバイス等の異なる環境でも汎用的に使用することができる。  


- ターミナルソフトを使用する場合の構成例
```text
入力デバイス(キーボード)
↓
入力モジュール(UART)
↓
CLIライブラリ
↓
出力モジュール(UART)
↓
出力デバイス(ターミナルソフトのコンソール画面)
```


- LCDを使用する場合の構成例
```text
入力デバイス(キーボード)
↓
入力モジュール(USB HID)
↓
CLIライブラリ
↓
出力モジュール(LCDデバイスドライバ)
↓
出力デバイス(LCDに描画)
```

---



## 機能
CLIライブラリには、キャラクタデータを入力する。  
キャラクタデータの解析を行い、テキストデータの作成・編集、または履歴操作等の機能を有する。  

テキストデータ確定時は、テキストデータをコマンドとして解釈しプログラムの実行を行う。  
また、キャラクタデータの入力・プログラムの実行結果に応じた出力をCLIライブラリは行うことになる。  



### ソフトウェア構成
役割毎に以下に分離する。  

- `Input Interface`  入力モジュールが受け取ったキャラクタデータをCLIライブラリに入力するためのインターフェース機能を提供する。
- `Command Module`   入力されたキャラクタデータの解析、コマンドラインの管理や、コマンドライン確定時のプログラム実行処理を行うモジュールを提供する。  
- `Output Interface`  CLIライブラリが生成した文字列データを外部へ出力するためのインターフェース機能を提供する。



### そのほか
キャラクタデータの文字コードは、`ASCII`コードを想定している。  
現段階では、そのほかの文字コード（UTF-8、Shaft_JIS等）については動作の保証はしない。  

作成・編集中のテキストデータはコマンドライン(現在の入力行)と記載し、内部ストレージ保存後のテキストデータを履歴と記載する。  


#### 設計判断

- CLIライブラリのソフトウェア構成は、入力・業務ロジック・出力の三段構成にする。
- コマンドラインの作成・管理とプログラム実行を責務として、入出力モジュールに関しては責務外とする。

---



### Input Interface
入力モジュールが受け取ったキャラクタデータをCLIライブラリに入力するためのインターフェース機能を提供する。  

利用者は、`Input Interface`用のAPIを使用しCLIライブラリにキャラクタデータを渡す。  
渡されたキャラクタデータは、`Command Module`が使用する。  

```c
void com_receive(uint8_t *p, uint32_t size)
{
    for(size_t i = 0; i < size; i++)
    {
        /* キャラクタデータをpush */
        cli_push(*p);
    }
}

void main(void)
{
    while(1)
    {
        /* push済みのデータ解析、コマンドラインの作成・編集を行う */
        cli_handler();
    }
}
```

このとき、入力は1byte単位のプッシュ方式で行い、キャラクタデータはFIFOバッファに格納される。

### Command Module
入力されたキャラクタデータの解析を行い、解析結果に応じてコマンドラインの作成・編集や履歴操作、コマンドライン確定時のプログラム実行を行う。  
キャラクタデータの解析結果毎に処理が分岐するため、目的とする処理ごとに機能を定義する。  

定義する機能を以下に記載する。  
いずれも、`Command Module`を介してのみ使用される機能として提供する。  

- `Command Line Editor` -コマンドラインの作成・編集や履歴操作を行う機能を定義する。
- `Command processor` -確定したコマンドラインの字句解析、解析後のコマンドラインに一致するプログラムの実行管理を行う機能を定義する。


キャラクタデータの解析結果毎に分岐する処理のフローは以下の通り。  

- コマンドラインの作成・編集
```text
キャラクタデータ入力
↓
解析した結果が文字であった
↓
コマンドラインの作成・編集
↓
結果出力(表示するコマンドラインの更新)
```


- コマンドライン確定時
```text
キャラクタデータ入力
↓
解析した結果がコマンドライン確定であった
↓
コマンドプロセッサー起動
↓
コマンドライン引数の作成、プログラムの実行
↓
結果出力(プログラムの実行結果を通知、プロンプトの再描画)
```

また、CLIから起動するプログラムは利用者がアプリケーションの目的に合わせて定義する必要がある。  
プログラム登録用APIを介して、定義したプログラムをCLIライブラリに登録する。  


---



#### Command Line Editor
コマンドラインの作成・編集や履歴操作を行う機能を定義する。  
作成するコマンドラインは、1単語のコマンド、もしくはコマンドとコマンドに付属する複数の引数で構成されることを想定する。  

- コマンドの1単語のみ
```shell
cmd
```

- コマンドと引数合わせた複数単語
```shell
cmd arg1 arg2 ...
```


また、キャラクタデータの種別によりコマンドラインの作成、編集に分岐する。  

1. **図形文字**  
   コマンドライン作成のため、キャラクタデータは現在のカーソル位置に挿入される。


2. **制御文字**
   コマンドライン編集のため、作成中のコマンドラインの編集、または特殊制御を行う。  
   以下の制御文字に対応する(種別は記号表記とする)。  

   - `BS(Backspace)` -現在のカーソル位置から文字を削除する。  
   - `LF(Line Feed)`  
     `CR(Carriage Return)` -両方、またはいずれかの入力は改行コードとして扱う。  
   - `ESCシーケンス`
     -エスケープシーケンスの入力に対応し、十字キーの入力で履歴呼び出し・カーソル移動に対応する。

#### Command processor
確定したコマンドラインの字句解析、解析後のコマンドラインに一致するプログラムの実行管理を行う機能を定義する。  
ENTERキー等の確定に関するキャラクタデータを受け取った場合は、コマンドラインの作成が完了したと判断し、プログラムの実行を行う。  

コマンドラインが確定した場合は、入力済みのテキストデータをスペースに区切りで分割し、プログラム実行時のコマンドライン引数として確保される。  

たとえば、コマンドラインを以下のように入力する。  

```shell
cmd arg1 arg2 ...
```

このとき、コマンドライン引数は、引数の数(argc)と引数文字列(argv)としてデータを保持する。  
コマンドライン引数の保証期間は、ENTERキーの入力から、プログラム終了までの期間となる。  

```c
int argc = 0;
char *argv[8];

/* 引数文字列 */
argv[0] = "cmd";
argv[1] = "arg1";
argv[2] = "arg2";

/* 引数の数 */
argc = 3;
```


コマンドの処理結果に関わらず、改行コード入力時のテキストデータはCLIライブラリの内部ストレージに保存する。

### Output Interface
`Output Interface`は、CLIライブラリが生成した文字列データを外部へ出力するためのインターフェース機能を提供する。  

CLIライブラリはUARTやUSB等の出力デバイスは責務としていない。そのため、利用者が出力モジュールを登録する方式を採用する。
利用者は使用するハードウェア環境に応じた出力関数を実装し、CLIライブラリへコールバックとして登録する。  

キャラクタ・テキストデータの出力時は、Output Interfaceから登録したコールバックへと責務を移譲する。  

```text
キャラクタ・テキストデータの出力を要求(Command Module or ユーザーアプリケーション)
↓
Output Interfaceの公開APIを呼び出し
↓
コールバック経由
↓
出力モジュール(UART, BLE, CDC等...)
```

#### ※メモ
`Output Interface`は、文字列・書式付き文字列・1文字出力が可能な公開APIを提供する。  
APIは、`Command Module`、またはユーザーアプリケーションが使用することを想定している。  

公開APIを以下に記載する。
- `cli_write`   -文字列を出力する
- `cli_printf`  -書式付き文字列を出力する
- `cli_vprintf` -va_listを利用した書式付き文字列を出力する
- `cli_putc`    -1文字を出力する

APIのモジュール階層を以下に記載する。
```text
cli_printf
↓
cli_vprintf
↓
vsnprintf(Standard Library)
↓
cli_write
↓
User Output Callback
```

出力用APIは`cli_write`を基本として、`cli_printf`および`cli_vprintf`は利便性向上のためのラッパAPIとして提供する。

#### 設計判断

- 出力機能は Output Interface に集約する。
- 出力デバイスには依存せず、コールバック経由で責務を移譲する。
- 基本APIは`cli_write`とし、printf系APIは利便性向上のためのラッパとして提供する。

---



### API利用シーケンス

```txet
cli_init()       # インスタンスの初期化、環境依存用の設定初期化
↓
↓
cli_register()   # CLIから事項するプログラムの登録
↓
cli_handler()    # 状態遷移(初期→アイドル移行)
↓
cli_input_char() # キャラクタデータ入力
↓
cli_handler()    # キャラクタデータの解析・プログラム実行
↓
cli_deinit()     # インスタンスの保持データ・設定を初期化
```

---



## 制約事項
- mallocを使用しない
- リアルタイムOS必須ではない
- 利用者が指定する設定は、Config用のデータを定義し、初期化時にConfigを渡す

- ASCIIを対象とする
- UTF-8は未対応
