# CLIライブラリ 設計メモ
検討内容を記載する。  


## 機能
CLIライブラリは、テキストのコマンドを入力し、マイコンの操作を実現するソフトウェアモジュールである。  

テキストデータの管理・コマンドの実行を行う`Command Module`と、キャラクタ・テキストデータの出力を行う`Output Interface`をCLIライブラリの機能として提供する。  
キャラクタデータの入出力や、テキストデータの描画は本ライブラリの責務とはしない。  

入出力・描画デバイスと、CLIライブラリの関連を示す図を以下に記載する。  

```text
キーボード等の入力デバイスから、キャラクタデータを入力
↓
=============================
入力モジュール(UART, BLE, CDC等...)
↓
CLIライブラリ
(テキストデータの作成・編集、コマンドハンドラー)
↓
出力モジュール(UART, BLE, CDC等...)
=============================
↓
コンソール等の表示器に入力結果を反映
```

また、キャラクタデータの文字コードは、`ASCII`コードを想定している。  
そのほかの文字コード（UTF-8、Shaft_JIS等）については動作の保証はしない。  

---



### Command Module
**Command Module**には、1byte毎のキャラクタデータをプッシュ方式で入力する。  
入力されたキャラクタデータが改行コードでない場合は、キャラクタデータからコマンドとなるテキストデータの作成・編集を行う。  
```text
キャラクタデータ(1byte)
↓
Command Module
↓
Command Line Editor　←　テキストデータの作成・編集
```


入力されたキャラクタデータが改行コードの場合は、入力済みのテキストデータを一文として確定する。  
テキストデータはコマンドとコマンドに付属する引数として解析し、コマンドの実行処理に振り分けが行われる。  
```text
キャラクタデータ(改行コード)
↓
Command Module
↓
Tokenizer 　←　テキストデータを字句解析
↓
Dispatcher　←　実行コマンドのディスパッチを行う
```


コマンドの処理結果に関わらず、改行コード入力時のテキストデータはCLIライブラリの内部ストレージに保存する。  
なお、作成・編集中のテキストデータをコマンドライン(現在の入力行)と記載し、内部ストレージ保存後のテキストデータは履歴と記載する。  

---



#### Command Line Editor
コマンドラインの作成・編集・履歴呼び出し、カーソル操作等の機能を定義する。  

`Command Line Editor`に渡されたキャラクタデータの種別による処理内容は分岐する。  

1. **図形文字**  
   コマンドラインとして使用可能なため、渡されたキャラクタデータは現在のカーソル位置に挿入する。


2. **制御文字**
   コマンドラインを編集する指示用データとして使用する。  
   以下の制御文字に対応する(種別は記号表記とする)。  

   - `BS(Backspace)` -現在のカーソル位置から文字を削除する。  
   - `LF(Line Feed)`  
     `CR(Carriage Return)` -両方、またはいずれかの入力は改行コードとして扱う。  
   - `ESC`
     -エスケープシーケンスの入力に対応し、十字キーの入力で履歴呼び出し・カーソル移動に対応する。  



コマンドラインは、1単語のコマンド、もしくはコマンドとコマンドに付属する複数の引数で構成されることを想定する。  

- コマンドの1単語のみ
```shell
cmd
```

- コマンドと引数合わせた複数単語(コマンドと引数合わせて8単語まで対応)
```shell
# 引数は最大で7つまで対応
cmd arg1 arg2 ...
```

---



#### Tokenizer
確定したコマンドラインの字句解析を行う機能を定義する。  

コマンドラインが保持するテキストデータを、コマンドライン引数にするためスペース区切りで分割する。  
コマンドライン引数は`Dispatcher`実行時にハンドラー経由で実行プログラムに渡される。  

たとえば、コマンドラインを以下のように入力する。  

```shell
cmd arg1 arg2 ...
```

このとき、コマンドライン引数は、引数の数(argc)と引数文字列(argv)としてデータを保持する。  
```c
int argc = 0;
char *argv[8];

/* 引数文字列 */
argv[0] = "cmd";
argv[1] = "arg1";
argv[2] = "arg2";

/* 引数の数 */
argc = 3;
```

コマンドライン引数の生存サイクルは、`Tokenizer`から`Dispatcher`の終了までの期間となり、以降はデータの保証はしない。  

---



#### Dispatcher
コマンドライン引数からコマンド(プログラム)のディスパッチャを行う機能を定義する。  

CLIライブラリが管理するコマンド(プログラム)が`Command Handler`に登録される。  
`Dispatcher`では、コマンドライン引数に一致するコマンド(プログラム)の振り分けを行う。  
`Command Handler`の起動時にコマンドライン引数は渡される。  

---



### Output Interface
`Output Interface`は、CLIライブラリが生成した文字列データを外部へ出力するためのインターフェース機能を提供する。  

CLIライブラリはUARTやUSB等の出力デバイスは責務としていない。そのため、利用者が出力モジュールを登録する方式を採用する。
利用者は使用するハードウェア環境に応じた出力関数を実装し、CLIライブラリへコールバックとして登録する。  

キャラクタ・テキストデータの出力時は、Output Interfaceから登録したコールバックへと責務を移譲する。  

```text
キャラクタ・テキストデータの出力を要求(Command Module or ユーザーアプリケーション)
↓
Output Interfaceの公開APIを呼び出し
↓
コールバック経由
↓
出力モジュール(UART, BLE, CDC等...)
```

#### ※メモ
`Output Interface`は、文字列・書式付き文字列・1文字出力が可能な公開APIを提供する。  
APIは、`Command Module`、またはユーザーアプリケーションが使用することを想定している。  

API候補を以下に記載する。
- `cli_write`   -文字列を出力する
- `cli_printf`  -書式付き文字列を出力する
- `cli_vprintf` -va_listを利用した書式付き文字列を出力する
- `cli_putc`    -1文字を出力する

APIのモジュール階層を以下に記載する。
```text
cli_printf
↓
cli_vprintf
↓
vsnprintf(Standard Library)
↓
cli_write
↓
User Output Callback
```

出力用APIは`cli_write`を基本として、`cli_printf`および`cli_vprintf`は利便性向上のためのラッパAPIとして提供する。

#### 設計判断

- 出力機能は Output Interface に集約する。
- 出力デバイスには依存せず、コールバック経由で責務を移譲する。
- 基本APIは`cli_write`とし、printf系APIは利便性向上のためのラッパとして提供する。
