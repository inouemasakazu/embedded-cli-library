# CLIライブラリ 設計メモ
検討内容を記載する。  


## 機能
CLIライブラリは、テキストのコマンドを入力し、マイコンの操作を実現するソフトウェアモジュールである。  

テキストデータの管理・コマンドの実行を行う`Command Module`と、キャラクタ・テキストデータの出力を行う`Output Interface`をCLIライブラリの機能として提供する。  
キャラクタデータの入出力や、テキストデータの描画は本ライブラリの責務とはしない。  

入出力・描画デバイスと、CLIライブラリの関連を示す図を以下に記載する。  

```text
キーボード等の入力デバイスから、キャラクタデータを入力
↓
=============================
入力モジュール(UART, BLE, CDC等...)
↓
CLIライブラリ
(テキストデータの作成・編集、コマンドハンドラー)
↓
出力モジュール(UART, BLE, CDC等...)
=============================
↓
コンソール等の表示器に現在のコマンドラインや処理結果を描画
```

また、キャラクタデータの文字コードは、`ASCII`コードを想定している。  
そのほかの文字コード（UTF-8、Shaft_JIS等）については動作の保証はしない。  

---



### Command Module
**Command Module**には、1byte毎のキャラクタデータをプッシュ方式で入力する。  
入力されたキャラクタデータが改行コードでない場合は、キャラクタデータからコマンドとなるテキストデータの作成・編集を行う。  
```text
キャラクタデータ(1byte)
↓
Command Module
↓
Command Line Editor　←　テキストデータの作成・編集
```


入力されたキャラクタデータが改行コードの場合は、入力済みのテキストデータを一文として確定する。  
テキストデータはコマンドとコマンドに付属する引数として解析し、コマンドの実行処理に振り分けが行われる。  
```text
キャラクタデータ(改行コード)
↓
Command Module
↓
Tokenizer 　←　テキストデータを字句解析
↓
Dispatcher　←　実行コマンドのディスパッチを行う
```


コマンドの処理結果に関わらず、改行コード入力時のテキストデータはCLIライブラリの内部ストレージに保存する。  
なお、作成・編集中のテキストデータをコマンドライン(現在の入力行)と記載し、内部ストレージ保存後のテキストデータは履歴と記載する。  

---



#### Command Line Editor
コマンドラインの作成・編集・履歴呼び出し、カーソル操作等の機能を定義する。  

`Command Line Editor`に渡されたキャラクタデータの種別による処理内容は分岐する。  

1. **図形文字**  
   コマンドラインとして使用可能なため、渡されたキャラクタデータは現在のカーソル位置に挿入する。


2. **制御文字**
   コマンドラインを編集する指示用データとして使用する。  
   以下の制御文字に対応する(種別は記号表記とする)。  

   - `BS(Backspace)` -現在のカーソル位置から文字を削除する。  
   - `LF(Line Feed)`  
     `CR(Carriage Return)` -両方、またはいずれかの入力は改行コードとして扱う。  
   - `ESC`
     -エスケープシーケンスの入力に対応し、十字キーの入力で履歴呼び出し・カーソル移動に対応する。  



コマンドラインは、1単語のコマンド、もしくはコマンドとコマンドに付属する複数の引数で構成されることを想定する。  

- コマンドの1単語のみ
```shell
cmd
```

- コマンドと引数合わせた複数単語(コマンドと引数合わせて8単語まで対応)
```shell
# 引数は最大で7つまで対応
cmd arg1 arg2 ...
```

#### Tokenizer
確定したコマンドラインの字句解析を行う機能を定義する。  

コマンドラインが保持するテキストデータを、コマンドライン引数にするためスペース区切りで分割する。  
コマンドライン引数は`Dispatcher`実行時にハンドラー経由で実行プログラムに渡される。  

たとえば、コマンドラインを以下のように入力する。  

```shell
cmd arg1 arg2 ...
```

このとき、コマンドライン引数は、引数の数(argc)と引数文字列(argv)としてデータを保持する。  
```c
int argc = 0;
char *argv[8];

/* 引数文字列 */
argv[0] = "cmd";
argv[1] = "arg1";
argv[2] = "arg2";

/* 引数の数 */
argc = 3;
```

コマンドライン引数の生存サイクルは、`Tokenizer`から`Dispatcher`の終了までの期間となり、以降はデータの保証はしない。  

---



#### Dispatcher
コマンドライン引数からコマンド(プログラム)のディスパッチャを行う機能を定義する。  

CLIライブラリが管理するコマンド(プログラム)が`Command Handler`に登録される。  
`Dispatcher`では、コマンドライン引数に一致するコマンド(プログラム)の振り分けを行う。  
`Command Handler`の起動時にコマンドライン引数は渡される。  

---



### Output Interface
**Output Interface**は、キャラクタ・テキストデータの出力を行うインターフェースとして定義する。  

CLIライブラリは、外部への入出力機能は責務としていない。  
そのため、Output Interfaceを使用する場合はCLIライブラリの初期化時に出力用モジュールのコールバック登録が必要になる。  

キャラクタ・テキストデータの出力時は、Output Interfaceの呼び出しを契機に登録したコールバックへ責務を移譲する。  

```text
CLIライブラリのCommand Module(またはユーザーアプリケーション)から、出力を要求
↓
Output Interfaceの呼び出しを契機に、コールバックを起動
↓
出力モジュール(UART, BLE, CDC等...)
```

## データ
組み込み向けの、軽量ライブラリとして提供するため以下を満たすこと。  

1. マルチインスタンスに対応するため制御データは構造体で一元管理とする。  
   インスタンスのメモリ領域は静的確保させる。内部staticデータ等も定義しない。  

2. 構造体は不透明型を採用し、CLIライブラリの制御データに対し外部からのアクセスはできないようにする。  
   APIを介する場合のみ、利用者は制御データの操作が可能となる。  

   また、公開する不透明型が確保するメモリ使用量は固定byteとする。  
   将来の拡張を考慮し、「64byte」とする。  

   ```h
   typedef struct
   {
       /* 不透明型を採用し、データ領域は64byteを確保する */
       uint8_t opaque[64]:
   } cli_handle_t;
   ```


3. CLIライブラリが使用するワークメモリは利用者が供給する。  
   コマンドライン用バッファ・実行コマンド(関数ポインタ)等の利用者によって必要とするメモリ使用量が異なるデータに関しては、利用者側に必要とするメモリ領域を保証してもらう。  

   コマンドライン用バッファは、利用者がメモリ領域の先頭ポインタと、メモリを使用する機能を通知する。  
   - メモリ領域の先頭ポインタ
   - メモリ領域のサイズ
   - コマンドラインの最大長
   - コマンドラインの履歴件数
   - 出力用バッファの最大長

   これらの設定から、メモリレイアウトと各機能に振り分けるメモリ開始位置のオフセットを算出しデータ構造内で管理する。  
   メモリを使用する機能は、メモリレイアウトとオフセットに応じて適切なメモリアクセスを行う。  

   実行コマンド(関数ポインタ)に関しても、利用者・アプリケーションが必要とするコマンド数が異なることを想定しており、固定長でコマンド用のメモリ領域を確保する必要はないと考える。そのため、コマンドの管理は連結リストを用いる。

   コマンドの先頭ポインタはCLIライブラリが保証し、先頭ポインタ以降の各ノードが必要とするメモリは、利用者側に保証してもらう。  


4. 利用者の環境に合わせた設定が必要なデータ用に専用のデータ構造を定義する、  
   例えば「3」で示したような、利用者がメモリ領域の確保であったり、任意の設定が必要なデータに関しては初期化用のデータ構造を定義し、設定が必要であることを明示する。  

   ```h
   typedef struct
   {
       /* ユーザーが個別に設定するデータを定義 */
       /* コールバック */
       /* ワークバッファ等... */
       int (*io_write_cb)(const char *p, uint32_t s);
   
       void *work;
       uint32_t work_mem_size;
   
       uint32_t max_line_length;
       uint32_t history_depth;
       uint32_t max_io_write_length;
   } cli_config_t;
   ```
